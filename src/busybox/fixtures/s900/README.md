# S-900 MediaSource fixture

`assets` contains five dedicated 640×360, 15fps VP8 WebM segments generated by FFmpeg. A luminous film marker crosses one numbered section in each reel, so the completed A→B→C→D stream is visually continuous. `lead.webm` is always prepended; `a.webm` through `d.webm` are selected by the player. The stage appends each already encoded reel once at an explicit `timestampOffset`; it does not repeat a borrowed frame or encode at runtime.

The stage's point is the real `MediaSource` append order, not a transcoder. Regenerate these Git-managed assets only with:

```powershell
$env:BUSYBOX_FFMPEG_PATH = "<trusted-ffmpeg-path>"
$env:BUSYBOX_FFPROBE_PATH = "<trusted-ffprobe-path>"
node scripts/generate-busybox-s900-s910-fixtures.mjs
```

`assets.test.ts` verifies the FFmpeg manifest, dimensions, frame counts, probe metadata, and each embedded WebM header.

FFmpeg's WebM muxer randomizes `TrackUID` even with bitexact flags. The generator normalizes the standard track UID and its tag target to a fixed value after encoding; it does not alter encoded frames. Running the same generator twice with the same toolchain therefore produces byte-identical Git assets without maintaining a separate checksum file.
