# 設計とデータの扱い

## メインスレッドを止めない

映像生成・エンコード・デコード・多重化はすべて専用ワーカー（[../workers/inspectionWorker.ts](../workers/inspectionWorker.ts)）で行う。UI 側は候補を 1 つずつ投げて進捗を受け取るだけである。

進行中のステージ更新では結果配列の参照を差し替えないため、472 行の一覧は再描画されない。行は `@tanstack/react-virtual` で仮想化し、DOM 上の行数を表示範囲ぶんに抑える。結果は新しいものから先頭に積まれるため、利用者がスクロール中なら挿入ぶんだけ位置を補正する。並べ替え中はこの補正を行わない。

## 経過時間と保存

中断して再開できるため、開始時刻からの経過には停止中の時間が含まれる。レポートは実際に検査していた時間の累計 `activeMs` を持ち、経過表示と残り見込みに使う。実用継続検査中は一括検査の時計を進めない。

実行中の結果はメモリ（Jotai）だけに置き、IndexedDB へ書くのは `complete` / `cancelled` / `failed` に達したときだけである。完全に完了したレポートは `previousCompleted` として 1 段だけ引き継ぐため、再検査を途中で中断しても直前の完全な結果は壊れない。

保存するのは設定値、成否、計測値、環境の概要のみであり、画面内容、音声サンプル、デバイス固有 ID は保存しない。

## 排他と更新通知

同時に複数の検査を走らせないよう Web Locks で排他する。オリジン単位なので、複数タブでも 1 つしか通らない。保存済みレポートの更新は BroadcastChannel で他タブへ伝える。

## 失敗コードと絞り込み

ワーカーが返す失敗・警告は `isConfigSupported-false` のようなコードで、レポートにもそのまま保存する。表示時に [../locales](../locales) の説明文を補うが、環境をまたいで報告・検索できるようコードも残す。詳細列の絞り込みは訳文とコードのどちらでも照合できるよう、言語に依存しない [../domain/filters.ts](../domain/filters.ts) へ照合用文字列を渡す。
